# 터레인 · 충돌 개선안

> 2026-08-03 조사. 코드 변경 없음.
> 문제의식: **격자로 400장 쪼개놓고, 그 격자를 공간 인덱스로 전혀 쓰지 않는다.**

## 0. 현재 격자의 실체

[ModelLoadManager.LoadHeightmapTerrain(20, 20)](../JWFramework/Manager/ModelLoadManager.ts#L156)

```
타일 400장 = 20 × 20,  피치 900,  타일 j 의 범위 = [j*900-450, j*900+450]
경계 76장 = dummy (세그먼트 1×1, 콜라이더 없음)
내부 324장 = 세그먼트 16×16 → 정점 289개, 삼각형 512개
저장 = objectList[OBJ_TERRAIN] 의 평면 배열, 인덱스 = 생성 순서 = i*row + j
```

**월드 좌표 → 타일 인덱스는 나눗셈 두 번이면 끝난다.**

```ts
const j = Math.round(x / 900);
const i = Math.round(z / 900);
const index = i * row + j;      // O(1)
```

그런데 이 계산이 **코드 어디에도 없다.** 격자가 있는데 선형 탐색을 한다 — 이게 문제의 뿌리다.

## 1. A군 — 격자를 공간 인덱스로 쓰기 (핵심)

### A-1. 광역 페이즈 전수 루프 제거 ★ 최우선

[ObjectManager.Animate():257-263](../JWFramework/Manager/ObjectManager.ts#L257)

```ts
CollideSphereToBox(objectList[OBJ_OBJECT3D], 비-dummy 터레인)   // N × 324
CollideSphereToBox(objectList[OBJ_MISSILE],  비-dummy 터레인)   // M × 324
```

오브젝트 하나가 **자기가 올라선 타일을 찾으려고 324장 전부와 sphere-box 교차 검사**를 한다. 오브젝트 50개면 프레임당 16,200회.

→ `WorldToTerrainIndex(x, z)` 로 **O(1) 배정**. 스피어 반지름이 타일보다 작으면 자기 타일 + 인접 8장만 보면 되고, 대부분은 자기 타일 하나로 끝난다.

> 이게 `inSectorObject` 가 원래 하려던 일이다. 지금은 **광역 페이즈를 없애려고 만든 자료구조를 광역 페이즈 전수 검사로 채우고 있다.**

### A-2. 지면 스냅을 레이캐스트에서 하이트필드 샘플링으로

[CollideRayToTerrain()](../JWFramework/Manager/CollisionManager.ts#L25) 은 오브젝트마다 `Raycaster.intersectObject(타일 메시)` 를 부른다 → 512 삼각형 순회. 못 맞히면 y=2000 에서 **한 번 더** 쏜다.

격자는 규칙적이므로 높이는 **바이리니어 보간으로 직접 계산**할 수 있다:

```
타일 로컬 uv → 정점 격자 (17×17) 의 네 꼭짓점 → 보간
```

레이캐스트 0회, 삼각형 순회 0회, 재시도 분기 불필요. 지형 위 어디서든 항상 답이 나온다.

### A-3. 타일을 LOD · 컬링 단위로

[HeightmapTerrain.Animate():362-372](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L362) 가 카메라 거리 4500 으로 `visible` 을 끈다. 격자 인덱스를 쓰면 **카메라 타일 기준 반경 k 링만 순회**하면 되고, 거리별로 세그먼트 수를 낮춘 지오메트리로 교체하는 LOD 도 같은 축에서 나온다.

## 2. B군 — 프레임 루프의 할당

매 프레임 새 배열/벡터를 만드는 지점들. 전부 GC 압력이다.

| 위치 | 내용 | 프레임당 |
|---|---|---|
| [ObjectManager.ts:259,263](../JWFramework/Manager/ObjectManager.ts#L259) | `filter(IsDummy == false)` — **불변인데 매 프레임 재계산** | 400 스캔 × 2 + 배열 2개 |
| [ObjectManager.ts:265](../JWFramework/Manager/ObjectManager.ts#L265) | `filter(inSector == true)` | 400 스캔 + 배열 1개 |
| [ObjectManager.ts:267](../JWFramework/Manager/ObjectManager.ts#L267) | `filter(IsClone)` | 배열 1개 |
| [HeightmapTerrain.ts:355](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L355) | `inSectorObject.filter(IsDead == false)` — **타일마다** | 배열 최대 400개 |
| [HeightmapTerrain.ts:362](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L362) | `GetPosition().clone()` — **타일마다** | Vector3 400개 |
| [CollisionManager.ts:70](../JWFramework/Manager/CollisionManager.ts#L70) | `filter().map()` 이 **바깥 루프 안에** 있다 | 물 타일 수만큼 |

조치: dummy/비-dummy 분리는 **생성 시 한 번** 확정해 캐시. `inSectorObject` 정리는 filter 대신 swap-remove. 거리 비교는 재사용 벡터 + `distanceToSquared()`(제곱근 제거).

## 3. C군 — `SetHeight()` 의 알고리즘 문제 ★ 브러시 렉의 주범

[HeightmapTerrain.SetHeight():262-285](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L262)

정점 **하나**를 고친 뒤 텍스처 판정을 위해 **289개 정점을 전부 순회**하는데, 그 루프 안에서:

```ts
if (cnt >= 30 && this.physicsComponent.GetMaxVertex().y <= 110)
```

[`GetMaxVertex()`](../JWFramework/Component/PhysicsComponent.ts#L118) 는 **자식 지오메트리의 모든 정점을 traverse** 한다(289개). 즉 **289 × 289 ≈ 83,000 정점 읽기**.

[Picker](../JWFramework/Picker/Picker.ts#L153) 는 `face.a/b/c` 로 `SetHeight` 를 **3번** 부른다 → **한 번 클릭에 약 25만 정점 읽기.** `T` 브러시 드래그면 이게 매 프레임이다.

→ 조치:
- `GetMaxVertex()` 를 루프 밖으로. 애초에 최대 높이는 `SetHeight` 가 **증분으로 추적**할 수 있다
- 텍스처 판정도 증분 카운터로 (전수 순회 불필요)
- `Picker` 는 3개 정점을 한 번에 넘기고 판정은 마지막에 1회

### C-1. `useDirtTexture` 가 한 번 켜지면 안 꺼진다 (버그)

```ts
if (getY(i) <= -3) useDirtTexture = true;
else if (i == positionLength - 1 && !useDirtTexture) useDirtTexture = false;
```

else 분기는 **이미 false 일 때만** false 를 넣는다. 지형을 깎아 사막 텍스처가 켜지면 **다시 올려도 되돌아오지 않는다.**

### C-2. `computeBoundingSphere()` 갱신 누락

[생성 시 1회](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L116)만 호출된다. `SetHeight` 로 지형을 높여도 바운딩 스피어는 그대로 → `frustumCulled = true` 가 **낡은 경계로 판정**한다. 산을 높이 세우면 화면 가장자리에서 타일이 사라질 수 있다.

## 4. D군 — 죽은 코드 · 잠복 버그

### D-1. `cameraInSector` 는 절대 `true` 가 되지 않는다

[CollisionActive():295](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L295) 과 [CollisionDeActive():313](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L313) **양쪽 다 `false` 를 넣는다.** Active 쪽이 `true` 여야 한다.

그 결과 [`GetInSectorTerrain()`](../JWFramework/Manager/ObjectManager.ts#L47) 은 언제나 빈 그룹을 반환하고, 호출부 3곳은 전부 주석 처리되어 있다. **카메라 섹터 기능 전체가 이 한 줄 때문에 죽어 있다.**

> 덤으로 카메라 대 터레인 검사(`CollideBoxToBox(TERRAIN, CAMERA)`)도 [주석 처리](../JWFramework/Manager/ObjectManager.ts#L254)라 이중으로 죽었다.

### D-2. 이웃 인덱스 계산이 정사각 격자에서만 맞는다

인덱스는 `i*row + j` 이므로 z 방향 이웃은 `index ± row` 다. 그런데 [코드는 `± this.col` 을 쓴다](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L242).
`row == col == 20` 이라 지금은 우연히 맞는다. **직사각 격자로 바꾸는 순간 이음매가 깨진다.**

### D-3. `HeightBuffer` getter 의 pop 루프

```ts
for (let i = 0; i < this.heightBuffer.length; ++i) this.heightBuffer.pop();
this.heightBuffer.length = 0;
```

`length` 가 줄어드는 배열을 `i < length` 로 돌아 **절반만 지우고**, 그 다음 줄이 어차피 전부 지운다. 첫 루프는 통째로 불필요.

### D-4. 매 프레임 유니폼 재대입

[Animate():339-346](../JWFramework/Object/CommonObject/Terrain/HeightmapTerrain.ts#L339) 이 타일 324장의 텍스처 유니폼을 **값이 안 바뀌어도** 매 프레임 대입한다. 플래그가 바뀔 때만 하면 된다.

### D-5. 디버그 잔재

[CollisionComponent.Update():208](../JWFramework/Component/CollisionComponent.ts#L208) — `OBJ_MISSILE` 마다 매 프레임 `console.log`. CLAUDE.md §2③ 에 적힌 그대로 아직 살아 있다.

## 5. 제안 순서

각 단계는 독립적으로 되돌릴 수 있고, 앞 단계가 뒤 단계의 전제가 되지 않게 배치했다.

| 단계 | 내용 | 기대 효과 | 위험 |
|---|---|---|---|
| **1** | D군 정리 (D-1 ~ D-5) + C-1 버그 | 동작 정상화. 코드량 감소 | 낮음. D-1 은 죽은 기능을 켜는 것이라 관찰 필요 |
| **2** | C군 — `SetHeight` 증분화 | **브러시 조작 체감이 가장 크게 바뀐다** | 중. 텍스처 판정 결과가 달라질 수 있음 |
| **3** | B군 — 할당 제거 | GC 스파이크 감소 | 낮음. 순수 최적화 |
| **4** | A-1 — `WorldToTerrainIndex` 도입, 광역 페이즈 교체 | **프레임당 충돌 검사 수가 자릿수로 감소** | 중. 섹터 등록 경로가 바뀜 |
| **5** | A-2 — 하이트필드 샘플링 | 레이캐스트 제거 | 중. 스냅 위치가 미세하게 달라짐 |
| **6** | A-3 — 타일 LOD | 원거리 정점 수 감소 | 중 |

**1~3 은 순수 정리·최적화라 눈에 보이는 동작이 바뀌면 안 된다.** 4~6 은 구조 변경이라 각 단계마다 브라우저 확인이 필요하다.

### 측정 방법

자동 테스트가 없으므로 **숫자를 먼저 고정**한다. `P` 키가 이미 `renderer.info` 와 삼각형 수를 출력하니, 여기에 다음을 붙이면 단계별 비교가 가능하다:

- 프레임당 sphere-box 검사 횟수 (A-1 전후)
- `SetHeight` 1회 소요 시간 (C군 전후)
- Stats 패널의 FPS · MS, 브러시 드래그 중 최저 FPS
